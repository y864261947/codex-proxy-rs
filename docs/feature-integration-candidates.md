# codex-proxy 功能整合候选清单

日期：2026-09-10。状态：需求讨论稿，供用户选择、修改和补充；不是已确认的开发范围。

目标：以自己的 codex-proxy-rs Fork 为基础，吸收 New API、Sub2API、CPA-Manager-Plus 的产品能力，保留当前 Codex 接入能力。用户已表达优先关注账号与后台管理，并希望账号导入同时改善迁移兼容和批量操作体验。后续补充重点为模型管理：新模型同步、定价同步、模型测试、图片/视频兼容，以及 OpenAI、Anthropic、Google Gemini、xAI/Grok、DeepSeek 等厂商接入。

本轮只整理候选功能，不修改业务代码、不迁移数据、不更新线上服务。

## 阅读方式

- 针对“上游接入 + 自建号池 + 按分组发 Key”的实际场景，优先参考 [功能收敛与菜单建议](navigation-and-scope-proposal.md)，再从本表选择实现范围。
- **增强**：当前已有相关基础，候选项描述新增的行为或体验。
- **新增**：当前公开接口、领域模型或页面中未提供对应的完整能力。
- **配套**：自有版本发布、迁移或运维所需的建设。
- **建议延伸**：根据参考项目提出的适配设计，不表示参考项目已经完整实现该行为。
- **规模小/中/大**：相对改造量，尚不是工期承诺；涉及账务、新 Provider、协议转换或多副本的项目通常为大。
- 所有编号初始均为**待定**。可回复“保留 A01、修改 B05、暂缓 G04”来逐步确定范围。

## 当前项目已经具备的基础

按本地 `ddc10d7c1acb426303e5291677a9b48bfc3105cf` 的接口、架构文档及前端代码核对：

- OpenAI/xAI OAuth 账号；OpenAI AT/RT、JSON、账号数组及 CPR 账号包导入；账号凭据导出与按上游身份更新。
- 账号分组、分页搜索、状态筛选、批量调度字段编辑、批量删除；新账号导入后默认未分组，重复导入保留原分组和调度设置。
- Client Key 分组授权、并发限制与 RPM 限制；Key 未绑定分组代表全部账号，绑定空池不会扩大权限。
- 智能、额度重置优先、轮询、粘性四种调度策略；账号权重、冷却、额度刷新和会话亲和。
- Responses HTTP/SSE/WebSocket、OpenAI 生图/编辑/独立搜索、模型目录和全局精确模型映射。
- 用量、成本估算、缓存、延迟、成功率、错误聚合、脱敏请求时间线和账号连接测试。
- 管理员登录、管理 API Key、后台审计记录、S3/R2 定时备份、版本检查、更新与回滚。

当前没有完整的普通用户平台、钱包与扣费账本、支付套餐、自定义渠道体系；不提供 Chat Completions、Claude Messages、Gemini 原生入口。架构明确限定单副本。这里的现状是**本地代码基线**，不等于服务器已经部署了同一 revision。

依据：[当前 API](api.md)、[当前架构](architecture.md)。

## 筛选建议与依赖

推荐优先讨论，不表示已经确认实施：

1. **第一批：账号与后台管理。** A01–A05、B01–B04、E01–E03、H02、I03。先补实际使用中的导入、管理和权限缺口；E01 若选择金额预算，需先确认计量/扣费边界。
2. **第二批：账号运营效率。** B05–B06、G01、H01/H03–H05、J03。巡检与自动化建立在明确的状态来源和处理规则之上。
3. **扩展路线一：更多上游和客户端。** C 与 D；分清“入口协议”“上游 Provider”“路由规则”，分别排期。
4. **扩展路线二：用户和商业化。** F → G02 → G03/G04/G05 → G06/I05。用户归属、账务与支付不能孤立加页面。
5. **发布前配套：J04。** 首次定制版上线前必须建立自己的镜像和更新来源。J05/J06 等确有需求后再设计。

新增重点：将 K01–K05、K08/K09/K12/K16 作为模型管理基础优先讨论。图片/视频建立在对应 Provider、目录、价格和任务适配上；K13–K15 可独立形成媒体能力批次。账号管理仍保留在候选范围内。

关键约束：

- 保留现有 Responses/SSE/WebSocket、工具调用、生图和身份语义；协议转换放在明确边界中，不能为了兼容其他客户端破坏原生路径。
- 导入凭据、导入用户、迁移余额/订单是不同任务。A 类不承诺直接搬运其他系统数据库。
- 账号组、用户组、计费套餐、上游渠道分别承担授权、归属、收费与转发职责，选定功能后先统一术语和关联关系。
- 账号巡检/自动恢复沿用证据来源，不把 HTTP 401/403 或缺失额度单独等同于封号；自动化不覆盖手工停用意图。
- CPAMP 是管理/观测面，实际转发依赖 CPA。借鉴它的管理体验不代表需要额外部署 CPA。
