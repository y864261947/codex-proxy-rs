## 不变量

- 旧 Key 权限范围与空池拒绝语义保持；流式交付后的请求不得换号重放。
- 数据库变更新增迁移，原有迁移 checksum 不变。
- 运行占用与完成日志分开；一次逻辑请求的多次上游尝试不能增加下游并发。
- 测试与探针不混入客户业务统计，但仍受真实来源容量约束。
- 生产服务和生产数据不作为开发测试环境。

## 批次 1 的实际行为

- `GET /api/admin/dashboard/realtime` 复用管理端鉴权与 `no-store`，直接读取共享内存计数；每 5 秒轮询不增加数据库查询。
- 入口 RPM 统计四个现有业务 POST 端点和 WebSocket 文本创建尝试，包括未通过认证/解码的请求；后台查询、模型列表、连接升级、空闲连接及内部账号探针排除。采用当前秒及之前 59 秒的固定桶，精度 1 秒。
- 实时并发是进入 Core 的逻辑执行数，拆分为准备中和执行中。重试不重复累计；失败、正常终态、取消收敛或会话丢弃释放计数。短暂的认证/解码阶段不计入执行并发。
- 指标仅覆盖当前单进程；重启清零，启动不足 60 秒和采样失败在 UI 明示。尚未引入队列和异步视频任务，不显示虚构的零值。
- 首页与监控中心复用实时负载卡片；监控中心同时展示既有号池容量和健康趋势（这些完成统计保持原有 30 秒刷新）。
- 自建号池下提供账号、号池分组两个入口；旧 `/accounts`、`/account-groups` 地址继续跳转，具名路由保留。
- 本批次未修改数据库迁移、下游 Key 权限和生产部署。

## 批次 2 开发记录

- 准入从单 Key 扩展为同一请求的多个独立限额范围；Redis 单次原子检查全部通过后才同时占用，并按请求 ID 幂等去重。
- 释放队列保存本次请求冻结的全部范围，客户归属后续变化不会误释放新客户的占用；RPM 记录在并发释放后保留。
- 已补充多个 Key 竞争同一客户容量、子级/父级拒绝无部分占用、重复请求与重复释放的测试；提交 `ace046a` 的 [CI](https://github.com/y864261947/codex-proxy-rs/actions/runs/34467429460) 全部通过，9 个 crate 共 1909 项主测试通过。
- 客户管理、持久化归属、统一来源与接入分组仍在开发，不能视为第二批完成。
- 新增 `0002_customers.sql`：客户及 Key 归属、历史请求客户引用；禁止删除仍有关联 Key 的客户。快照读取客户启用状态与独立限额，历史恢复不依赖当前客户/Key 行。
- 客户禁用认证、快照冻结、两种请求落库路径与改归属/删除后的恢复测试已编写。首轮数据库测试中两个新增 fixture 漏写 Key 表必填时间戳，已补齐；没有修改原表约束，修正后的完整版本等待 CI 验证。
- 新增客户管理端口、服务和管理员接口，创建/编辑/删除/Key 归属更新与配置版本和安全审计原子提交；冲突回滚版本与审计，关联客户名称和状态进入 Key 列表投影。
- 下游接入下提供 API 密钥、客户两个分区；客户页管理共享限额和启停，Key 列表独立设置归属。客户查询与选择提供搜索/分页/加载失败反馈，归属修改要求明确选择客户或解除归属。
- 独立模拟 API 的浏览器检查覆盖客户创建、4 并发/60 RPM 保存、搜索后保留选择、归属更新、客户停用、加载失败禁止保存及重试恢复。发现独立客户列被固定操作区遮挡，已改为名称下入口；客户停用显示为 Key 状态。该检查不替代真实后端集成测试。
- 客户关联后的 PostgreSQL 回归测试发现 Key 游标排序及搜索条件存在未限定列名，已统一使用 Key 表别名；`ON DELETE RESTRICT` 返回的 `23001` 已映射为冲突，保证失败操作回滚版本、审计与归属。
- 接入分组核心策略与 `0003_access_groups.sql` 已实现：独立组 ID、精确模型白名单、显式号池集合、组并发/RPM，模型列表与执行授权共用策略。空模型/空号池不退化为全部权限；未关联接入分组的旧 Key 保留原语义。
- 请求在模型别名映射之前检查对外模型权限；使用接入分组的 Key 调用 Provider 原生端点时，必须提供由 Provider 识别的已授权模型，无模型请求拒绝，旧 Key 的原有原生端点行为不变。
- 组归属冻结在请求历史与释放范围内，重启恢复从历史读取。新增快照隔离、模型别名授权、空池拒绝、禁用组、改组/删除后恢复和双落库路径测试。接入分组管理接口/页面及渠道来源尚未完成，此阶段等待 CI 验证。
