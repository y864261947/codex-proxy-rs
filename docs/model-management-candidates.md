# 模型管理、价格同步与多模态兼容候选清单

日期：2026-09-10。状态：需求讨论稿，补充 [总清单 K01–K16](feature-integration-candidates.md)。本轮只修改需求文档，没有添加网关实现、执行付费模型测试或更新线上服务。

## 用户明确关注的方向

- 新模型同步、定价同步、模型测试。
- 图片、视频模型的兼容性。
- OpenAI、Anthropic/Claude、Google Gemini、xAI/Grok、DeepSeek 等主要厂商。
- 三种接入方式均纳入范围：官方 API Key、现有 OAuth 账号、第三方渠道；这不表示每家厂商都需要或具备 OAuth 订阅转发支持。
- 继续以 New API 的渠道/模型管理、Sub2API 的分组与账号接入、CPA-Manager-Plus 的价格与观测作为产品参考。

## 产品目标与当前差距

菜单归属及与下游分组的职责划分见 [功能收敛与菜单建议](navigation-and-scope-proposal.md)。

模型的持续健康观测、定时探针和供应商分类见 [渠道与自建号池监控](monitoring-proposal.md)。模型详情展示关联状态与测试证据；探针任务在监控中心统一管理，复用模型的协议与能力适配。

把模型目录、同步、定价、测试、能力和发布放入同一个管理入口。可以从一个模型看到：谁提供它、哪些渠道可用、支持什么请求、采用什么价格、何时测试过、哪些 Key 能调用。

当前已有 OpenAI/Codex 与 xAI/Grok 的模型目录、套餐目录缓存、能力证据、账号模型刷新、模型映射、成本估算和账号连接测试。需要新增跨厂商的管理中心，并扩展官方 API Key/第三方渠道、新 Provider 和媒体任务能力。

概念需要分开记录：

1. **厂商模型**：官方发布的模型、版本、声明能力。
2. **渠道模型**：某个 URL、凭据类型、账号/项目/地域实际暴露的模型及价格。
3. **公开模型**：对用户展示的名称、别名、允许范围和路由。
4. **测试证据**：在指定时间、渠道、端点、参数下实测了什么。

官方模型列表出现某个 ID，不能证明该模型在所有凭据和所有端点上可用。已有 OAuth 订阅账号目录也不能作为官方 API Key 全部能力的依据。

同一厂商模型可关联多个渠道，各渠道分别记录凭据方式、上游模型 ID、可用能力、价格、权限和测试证据。模型名字相同不自动合并成完全等价的供应，不共享未经验证的可用性判断。

## 16 个候选功能的重点行为

### 模型发现与资料：K01–K04

- 支持手动同步和可配置定时同步，记录每个来源的状态、时间、分页完成情况、数量和错误。
- 新增模型进入待处理列表；改名/别名漂移、能力变化、弃用/关停通知分别展示。
- 保留最近成功快照；请求失败、权限变更、分页不完整或暂时消失，不直接删除本地模型和历史引用。
- 模型能力使用独立输入/输出维度：文本、图片、音频、视频；再描述工具调用、结构化输出、流式、推理档位、上下文和参数限制。
- 图片理解、生图、图片编辑、视频理解、视频生成互不替代。能力缺失保持未知，不仅靠模型名字推断。

### 价格同步与版本：K05–K08

- 同步渠道模型列表与同步价格是两套操作，不能假设所有 `/models` 都携带价格。
- 建议来源顺序：可用的官方结构化字段 → 维护过的官方价格数据适配 → 经明确身份匹配的 models.dev/LiteLLM/OpenRouter 数据。无可靠匹配时进入待确认列表。
- 官方文档价格并不等于统一可机读接口；对于没有结构化接口的厂商，需要维护适配数据和来源证据，不能承诺完全无人维护。
- 手动覆盖不被后台同步覆盖；上游参考价、渠道采购/订阅成本与对用户售价分开。
- 标准化币种、金额精度、每 Token/百万 Token/图片/秒等单位，同时保留原始值。未知价格与明确零价格分开。
- 支持缓存读写、长上下文、Batch/服务档位、峰谷时段、图片质量/尺寸、视频时长/分辨率/是否含音频等维度；具体维度按模型文档启用。
- 同步展示前后差异、生效时间和来源；建议初期只自动发现变化，由管理员应用改价。是否允许自动应用属于待选策略。
- 正式扣费保存使用量和价格版本，不因今天同步新价格而回写昨日账务；成本估算的重算也应有独立标识。

### 模型测试与兼容性：K09–K12

- 指定模型、渠道/账号、协议、参数和测试类型，显示结果与错误，不仅以 HTTP 200 或能列出模型作为通过。
- 文本测试：普通响应、SSE/流式终态、工具调用往返、结构化输出；不同端点分别测试。
- 图片测试：输入识别、生图、编辑按能力分别测试；验证返回的文件/MIME/预览，不能拿文本回复代替真实图像结果。
- 视频测试：提交任务、获得上游任务标识、查询终态、获取并预览产物；等待中、轮询失败和生成失败分别显示。
- 保存首包/首 token/总耗时、使用量、价格版本及结果证据；未返回使用量时明确标为未知。模型测试与生产用量可区分查询。
- 批量比较同模型不同渠道；统一输入和测试参数，展示样本数量与测试时间，结果只代表测试条件。
- 媒体和批量测试可能消耗上游额度，应显式选择运行并设置测试并发/预算；定时同步不隐含触发付费测试。
- 兼容矩阵分别记录官方声明、渠道可用性、网关适配和实测结果。网关适配状态可用原生/已适配/部分支持/待适配/不支持表示；测试状态另行展示。

### 图片、视频与发布：K13–K16

- 图片按 Provider 适配上传、URL/base64/文件返回、编辑蒙版、多参考图、比例、分辨率、质量和透明背景等；只暴露该型号确实支持的选项。
- 视频统一呈现任务生命周期，保留厂商任务 ID、进度是否真实可得、轮询状态、失败原因和产物有效期。取消仅在上游支持时暴露；否则不能把本地停止等待称为取消生成。
- 上游已接单但本地超时的任务进入待核对状态，优先继续查询，避免自动重复提交带来重复生成和费用。
- 素材与产物按需持久化到对象存储，明确访问权限和保留期限；链接失效不应继续展示为可下载。跨厂商视频提交/查询路径不同，不能只改 Base URL。
- 对外保持已验证的原生协议；提供统一管理体验或公共任务接口时，明确兼容子集并保留必要厂商参数。不支持的参数明确报错，不静默丢弃。
- 发布控制独立于同步：模型别名、所属渠道、价格、权限和测试结果可一并检查，再按策略启用。新的语义或接口仍需要适配代码，无法单靠同步模型 ID 自动获得支持。

## 测试工作台与图片、视频测试体验

本节为针对用户菜单与多模态测试问题的建议，尚未确认为最终界面。建议暂不增加一级“模型测试”菜单，在“模型管理”内部提供独立页面“测试工作台”，与“模型目录”“价格管理”并列。模型、渠道、号池和分组页面保留“测试”快捷入口，跳转后预填上下文；复杂素材和异步结果不塞进连接测试弹窗。未来测试成为每日主要任务时，可将同一个页面提升到一级入口，不新建另一套测试系统。

### 页面与测试目标

页面左侧为来源选择、输入素材和参数，右侧为结果与耗时/用量；下方提供测试历史。文本、图片、视频共用运行记录，但使用各自的输入和结果组件。原始请求与响应、厂商专有参数放在高级详情中，默认提供可操作的表单与媒体预览。

两种测试模式应明确区分：

- **指定来源测试**：选择供应商、模型、渠道或号池；需要定位账号问题时再指定账号。固定来源，不允许通过备用渠道成功掩盖目标失败，记录实际上游模型和账号。
- **按分组调用测试**：使用所选测试 Key 的真实权限，经与下游一致的鉴权、分组、模型映射和路由路径调用。结果展示所用来源和切换记录，不使用管理员权限绕过分组限制。凭据不回显到日志、历史或分享内容；停用或到期的 Key 应得到对应鉴权结果。

在选择目标后，按已确认的能力提供操作：文本生成、图片理解、文生图、图片编辑、视频理解、文生视频、图生视频。其他能力如首尾帧、多参考图、视频编辑或延长，仅在对应适配就绪时显示。支持格式、大小、比例和取值范围从模型/来源能力配置读取，切换目标时提示哪些参数需要调整，不能静默丢弃。

### 图片测试

| 操作 | 输入与参数 | 结果与检查 |
| --- | --- | --- |
| 图片理解 | 上传图片并输入问题，可使用带已知答案的示例图 | 显示原图和回答；“图片已被接收”与“回答内容正确”分别检查 |
| 文生图 | 提示词、目标支持的尺寸/比例、质量、数量、格式及背景选项 | 缩略图、放大预览、下载；检查实际文件可解码、MIME、尺寸、数量与请求是否匹配 |
| 图片编辑 | 原图、修改描述；遮罩、多参考图等按支持情况开放 | 原图/结果并排或滑动对比；检查生成产物，并人工评价指定区域修改与主体保留 |

快捷验证默认生成一张、使用目标支持的较低成本配置；真正验证图片生成必须产生图像，列出模型或返回一段文字只证明相应步骤可用。内容过滤、有效拒绝、参数错误、网络失败、上游生成失败与预览失败分别记录。

可提供“简单物体”“含文字海报”“参考图主体保持”等合成测试模板。自动检查接口和产物基本有效性；文字准确性、构图和编辑效果保留人工评价。未来可增加辅助评分，但不能把评分等同于服务健康或保证模型效果。

### 视频测试

视频工作区提供文生视频、图生视频，以及已适配的首尾帧/参考素材等操作。视频理解使用“上传视频 + 提问”的单独模式，不能通过分析视频来宣称具备生成能力。

流程为“选择目标 → 输入提示词/素材 → 设置支持的时长、比例、分辨率及音频选项 → 查看预计用量/费用 → 开始测试 → 查看任务与播放器”。快捷测试默认一条、采用该目标支持的较短时长和较低成本规格；无法可靠估价时显示未知，并给出已选规格与数量。

- 服务端保存本地测试 ID 与上游任务标识，负责跟踪终态；关闭页面或浏览器后任务仍可查询，重新进入继续显示同一任务。刷新页面不重新生成。
- 显示提交中、处理中、已完成、生成失败等有依据的状态；上游不提供排队阶段或进度百分比时不虚构。轮询失败与生成失败分开，提交结果不明时进入待核对状态。
- 结果包含播放器、封面、实际时长/分辨率、是否含音轨、总耗时、使用量与费用。文本首字时间不作为视频生成速度指标，不能仅收到任务 ID 就标记完整测试通过。
- 自动检查任务终态和视频可访问/解码、时长及规格；播放后人工评价动作连续性、主体一致性、提示词遵循及音画表现。
- 区分上游生成成功但产物获取失败、媒体格式有效但浏览器无法播放、资源链接已过期。结果可按配置保留到受控存储，显示保留期限；下载权限与原测试一致。
- 只有上游具备取消能力并确认取消时，才显示“已取消”。本地停止查询不等于上游停止生成或停止计费。
- 超时后优先继续核对原任务；“重新生成”创建新的运行记录并明确属于新的调用，不自动反复提交。

这些设计适配真实厂商的任务语义。例如 [xAI 视频生成文档](https://docs.x.ai/developers/model-capabilities/video/generation) 明确提交后返回任务标识、随后查询状态，结果 URL 具有临时性。[Gemini 图片文档](https://ai.google.dev/gemini-api/docs/image-generation) 则分别描述生成与基于输入图片的编辑。界面统一，但各厂商的参数和执行协议保持独立适配。

### 测试结果、对比与监控复用

一条测试记录分开保存三类结果：调用与协议是否通过、产物/结构是否有效、效果评价。保存目标供应商/模型、实际渠道/账号、协议、模板与参数版本、耗时、用量、费用估算依据、终态和可访问的产物证据。未检查、未知与不支持分别显示；一次通过不表示该模型所有能力都已验证。

支持用同一提示词和素材对比 A/B 来源或不同模型。开始前列出将发出的测试数量与预计费用；展示实际使用参数、缓存状态、运行时间和来源，不能因同名参数取值相同就假设不同模型完全等价。随机种子仅在支持时开放，即便相同也不保证跨厂商可重现。单次试跑不自动生成可靠性排名。

测试历史提供“复用参数”而非静默重跑；每次新的生成均由用户明确开始。长期媒体任务统一保存在“请求与用量 → 媒体任务”，工作台与模型详情只展示筛选后的同一份任务，避免两套状态相互矛盾。

模型测试用于人工验证接入、能力、效果与下游路径；监控探针用于持续检测。手动测试与探针可以复用模板和执行适配，但分别记录运行类型，运维测试费用独立统计，不混入客户消费。测试标记不免除并发约束：所有测试受来源/账号容量限制，按分组调用测试仍检查所选 Key、客户和组的权限及限额。“保存为探针”进入监控配置页，由用户选择周期、预算并启用；图片/视频测试不自动变成高频生成任务。

## 五类厂商的接入方向与已核对差异

这张表描述需求选型方向，不表示当前项目已经兼容。型号、账号权限和供应商接口会变化，实际接入时再次核对。

| 厂商 | 模型发现与资料 | 图片/视频集成方向 | 需要区分的接入方式 |
| --- | --- | --- | --- |
| OpenAI | 官方 Models API 提供基本模型资料及可选关停日期；完整能力和价格需要结合模型文档。当前项目的 Codex OAuth 目录继续独立维护。 | 保留现有图片能力，扩展所选官方图像模型；Sora 2/Videos API 已公告将关停，不建议作为新视频接入首选。 | Codex/ChatGPT OAuth、官方 API Key、第三方兼容渠道分别核对。 |
| Anthropic / Claude | 官方 Models API 提供模型资料、部分能力及上下文信息。 | 优先文本/推理/工具调用/图片理解；本轮查阅材料未建立官方图片或视频生成接口的依据，不预先标记为支持。 | Anthropic 直连、云平台渠道和订阅账号各自认证与模型 ID 不能混用。 |
| Google / Gemini | Models API 支持模型列表、Token 限制和支持的生成方法。 | 分别接入文本/多模态理解、图像生成/编辑与视频生成。当前视频文档分别列出 Gemini Omni Flash 和 Veo，不能将所有视频能力固定在一个旧型号。 | Gemini Developer API 与 Vertex AI 的认证、项目/地域、模型标识和价格分别管理。 |
| xAI / Grok | 官方 API 除通用列表外，还提供语言、图片生成、视频生成的详细目录；部分包含价格和输入/输出类型。 | 选定官方图像/视频型号并适配相应生成任务；不能从当前 Grok CLI OAuth 文本目录推断这些能力。 | 当前 CLI OAuth 账号与 xAI 官方 API Key 是不同路径。 |
| DeepSeek | Models API 提供模型列表；官方模型/价格页包含能力、缓存价格、别名及峰谷规则。 | 优先文本、推理、工具调用及具体型号支持的视觉输入；本轮文档没有建立官方图片/视频生成接口的依据。 | 官方 API 与第三方托管渠道分别测试，不能给同厂商所有型号打相同能力标签。 |

官方依据：

- [OpenAI Models API](https://developers.openai.com/api/reference/resources/models/methods/list)、[模型目录](https://developers.openai.com/api/docs/models/all)、[视频文档](https://developers.openai.com/api/docs/guides/video-generation)。
- [OpenAI 弃用公告](https://developers.openai.com/api/docs/deprecations)：截至 2026-09-10，公告规定 Sora 2 和 Videos API 于 **2026-09-24** 停止服务。这是模型管理需要关停日期与迁移提示的实例。
- [Anthropic Models API](https://platform.claude.com/docs/en/api/models)、[Claude 视觉](https://platform.claude.com/docs/en/build-with-claude/vision)、[Claude 定价](https://platform.claude.com/docs/en/about-claude/pricing)。
- [Gemini Models API](https://ai.google.dev/api/models)、[视频生成](https://ai.google.dev/gemini-api/docs/video)、[定价](https://ai.google.dev/gemini-api/docs/pricing)。
- [xAI Models API](https://docs.x.ai/developers/rest-api-reference/inference/models)、[视频生成](https://docs.x.ai/developers/model-capabilities/video/generation)。注意部分文本价格字段使用“每一亿 Token 的美分”，图片还包含规格价格矩阵，必须按字段单位转换。
- [DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models)、[模型与定价](https://api-docs.deepseek.com/quick_start/pricing/)。该页对具体型号的视觉能力、缓存命中/未命中价格、峰谷时段和别名变化有独立说明。

## 对三个参考项目的取舍

- **New API**：借鉴模型与渠道绑定、模型映射、多协议适配、模型权限和测试入口；不因为通用兼容接口可用就默认所有专有功能可用。
- **Sub2API**：借鉴不同凭据类型、组级路由/价格、媒体任务和账号可用性；保持渠道、账号、组、模型的归属清晰。
- **CPA-Manager-Plus**：借鉴价格来源、同步匹配确认、价格变更和模型用量/故障观察；其价格估算机制不能直接充当用户扣费账本。

参考：[New API](https://github.com/QuantumNous/new-api)、[Sub2API](https://github.com/Wei-Shaw/sub2api)、[CPAMP 价格管理](https://seakee.github.io/CPA-Manager-Plus/docs/en/manual/model-prices.html)。

## 推荐讨论顺序与尚待选择的内容

1. 先确定 K01–K05、K08/K09/K12/K16 的模型管理基础：目录、同步、来源、兼容矩阵、测试、发布。
2. 官方 API Key/渠道架构准备好后，逐厂商接入；现有 OAuth/Codex 能力保持独立验证。
3. 图片与视频分别形成适配批次，优先选择有真实使用需求和有效接口的型号。视频依赖任务与产物管理。
4. 涉及正式用户扣费时再接 G02/G03，并使价格版本、媒体任务和账务一致。

待用户完善：首批厂商与渠道顺序、同步周期、是否允许自动上线/自动改价、测试预算、具体图片/视频操作与产物存储期限。三种接入方式已确认都要支持；此处其余推荐行为均为讨论默认值，不代表已经确定具体开发范围。
